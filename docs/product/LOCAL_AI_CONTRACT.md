# Windows-local AI

Genuine local inference is required current scope. All runtime claims start UNVERIFIED. The product uses pinned multilingual-e5-small ONNX INT8 CPU artifacts, tokenizer and license in a bounded process on the employee's Windows machine in BOTH standalone and connected modes. Inference does not run in the browser, hosted API or an external AI provider. External provider APIs are prohibited, including fallback during model/CPU/network errors.

## 1. Outputs and canonical boundary

The advisory process supplies semantic CV–JD evidence ranking, conservative rule-plus-AI information-to-verify findings and editable Vietnamese interview questions from versioned templates. An embedding measures text similarity; it is neither free-form generation nor proof of skill, honesty or employment. Temporal overlap and incomplete history may warrant a neutral verification question; they never establish fraud. Findings cannot deduct points, change stage or automatically confirm facts.

Canonical ratings, scores, mandatory status and calculation identity remain governed by [the product score contract](PRODUCT_SPEC.md). Confirming a finding as a reviewed fact creates a new attributed profile revision and a new evaluation when requested. Updating model/rule/template alone cannot alter historical canonical evaluation. Advice is stored/reviewed separately and never submitted as numeric criteria, thresholds or weights.

## 2. Artifact and numeric contracts

Phase 02 must pin immutable upstream revision, ONNX graph hash/opset/quantization provenance, tokenizer files/hashes, license/redistribution evidence, CPU execution provider/runtime, supported CPU baseline, text preprocessing/chunking/pooling/normalization, ranking/tie rules and output precision. Phase 14 packages the pinned artifacts; there are no runtime downloads. Build-time acquisition is from official sources with license review, not an external inference service.

The [upstream model card](https://huggingface.co/intfloat/multilingual-e5-small/raw/main/README.md) documents 384-dimensional embeddings, retrieval prefixes, masked average pooling/L2 normalization and a 512-token input ceiling. The [upstream ONNX directory](https://huggingface.co/intfloat/multilingual-e5-small/tree/main/onnx) identifies MIT license metadata and lists an INT8 artifact named `model_qint8_avx512_vnni.onnx`. These references do not establish compatibility with every target CPU. Phase 02 must verify an appropriate pinned INT8 CPU artifact or reproducible licensed conversion for the approved Windows x64 baseline, rather than infer compatibility from that filename. [ONNX Runtime quantization documentation](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html) warns that quantization may affect quality; actual product comparisons and inference qualification are required.

Retrieval treats JD criteria as queries and approved CV evidence chunks as passages. The pinned adapter must account for prefixes and special tokens within the model ceiling, preserve page/span locators and report bounded omissions; long CVs cannot be silently represented as fully processed. Chunking, overlap, maximum input and truncation reporting are versioned contracts, defined numerically in Phase 02. Sensitive/contact/protected fields are excluded from advisory features unless strictly needed for an authorized evidence display; no discriminatory rule may rank or flag protected traits.

Similarity internals may use versioned floating-point computation and documented precision. The Phase 02 adapter specifies finite-value validation, display representation, precision/quantization for stable ordering, descending rank and deterministic stable semantic locator as final tie-break. Golden/rerun checks document actual precision and permitted numerical tolerance without claiming bit-identical floats on every CPU. Similarity must be labeled advisory and cannot become persisted canonical score/threshold/weight. A persisted advisory measurement is part of an advisory run only; canonical components never reference it numerically.

## 3. Resource, task and privacy ownership

The initial maximum peak AI-process resident working set is 1.5 GiB, exactly 1,610,612,736 bytes. The budget is supplied by validated central resource configuration with a versioned owner; it is an agreed required ceiling, not a measured current result. Phase 02 defines positive bounded threads, queue/concurrency, batch size, document bytes/pages/text/chunks/tokens, timeout/cancellation, temporary storage capacity and cleanup durations. No unapproved numeric defaults are invented in Phase 01. Validate before load and again when a task obtains current policy.

Load on demand, release resources according to explicit idle/task policy, and use one owned local inference process per admitted task/concurrency contract. Prohibit unbounded children or fragmented processes used to evade the budget. Measure actual Windows inference PID and any owned helper PIDs; report individual peaks and sampled simultaneous aggregate working set, sampling interval and startup/load coverage. Enforce the 1.5 GiB ceiling on the complete admitted inference process workload; helpers cannot be omitted. Use OS peak/current working-set counters, not model file length, Python object counts, commit charge alone or UI-process memory. Windows exposes process working-set statistics through [GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo) and [PROCESS_MEMORY_COUNTERS](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters). Phase 18 records the chosen sampling/peak methodology and its limits.

For connected advice, the central server issues a purpose/version/evidence-limited approved input snapshot manifest after current staff authorization. It includes realm/agency/person/privacy epoch, application/JD/profile/evidence versions, permitted task, expiration and revocation authority. Employee Windows stores any downloaded CV/snapshot only in protected owned temporary storage; no shared browser download directory or cross-realm reuse. Local task inputs/derivations expire under current policy and are removed on expiry, revocation, cancellation, logout/mode switch as applicable and restart recovery. Offline connected input cannot silently become standalone data. Loss of server authority prevents attachment/final commit; bounded cleanup still runs.

An advisory attachment contains manifest/input/evidence references, model/runtime/rule/template versions, deterministic ranking definition, process/execution metadata, output status and review provenance. Server validates current identity/membership/purpose/consent, approved input/evidence/manifest/version/expiry/privacy epoch and allowed output shape before a guarded audited commit. Client claims about model execution, device identity or hash are not authentication or proof of execution. Server records provenance without pretending remote attestation exists. Genuine execution is qualified from controlled actual Windows evidence in owner phases; server authorization remains necessary on every attachment.

## 5. Offline corpus and quality measurements

Phase 12 owns generated import/batch handling. Phase 18 owns the 100-CV measurement corpus and quality qualification; Phase 10 supplies initial golden inference/meaning checks. Corpus contains labeled synthetic Vietnamese and mixed-language job-relevant evidence, clear matches/nonmatches, ambiguous overlap, incomplete history, tied rankings, long/bounded inputs, malformed/unsupported cases, Unknown criteria and protected-trait variations. All 100 corpus items get a terminal success/failure/cancelled status with no omitted failure. Failure expectations are explicit in the corpus manifest; a designed invalid PDF rejection is not a claimed successful inference. Required valid-input inference failures block qualification until repaired.

Each row must include corpus ID/hash (synthetic), JD/rubric/profile/evidence versions, input and artifact manifest identities, execution mode, CPU/OS/runtime/settings version, task/PID/owned helpers, cold/warm flag, status/error class, processed/omitted chunks, elapsed wall time, peak working set/measurement method, cleanup outcome and quality annotations. Record total attempted/succeeded/expected-rejection/unexpected-failure counts, elapsed distributions including failure timing, memory maxima and all failure details without personal text/secrets.

Human annotation defines relevant semantic spans, safe verification findings and acceptable Vietnamese questions before evaluation. Report evidence relevance at versioned top-k with denominator/ambiguous judgments, false-alert numerator/denominator including no-finding controls, and question grounding/readability/editability judgments with named rubric/version. Do not infer recruitment accuracy from embedding benchmark scores. Safe output floors require zero claims of proven fraud from overlap/missing history, zero prohibited-trait numeric influence, zero advice-triggered score/stage changes and no unsupported factual accusation in template output. These floors follow agreed invariants; useful-suggestion and timing thresholds remain OPEN for Phase 02 contract definition and Phase 18 owner approval before measurement. Do not choose targets retrospectively to force PASS.

Qualification records process/network observation confirming no runtime model download or external-provider request. Connected snapshot transmission is to the approved application server only and is disclosed accurately. Offline standalone qualification and approved HTTPS connected qualification remain independent required gates under [release](RELEASE_CONTRACT.md).
